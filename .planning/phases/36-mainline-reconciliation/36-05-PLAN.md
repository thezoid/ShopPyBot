<dependabot_procedure>
Identical shared decision tree to plan 04. Restated here so this plan is self-contained.

STEP 1, re-derive live state: `gh pr view <n> --repo thezoid/ShopPyBot --json state,mergeStateStatus,title,files,additions,deletions,headRefOid`. Already `CLOSED` or `MERGED` means GitHub resolved it: record and skip to STEP 6.

STEP 2, direction check: read the PR's target action version from its title and diff, then read what master's `.github/workflows/ci.yml` currently pins with `git show origin/master:.github/workflows/ci.yml`. If master is already at or above the target, the PR is superseded: go to STEP 5. If master is older, go to STEP 3. This matters more than usual here: the PR #11 merge took the branch's newer `actions/checkout@v6` and `actions/setup-python@v6` pins over master's `@v4` and `@v5` (36-RESEARCH.md "State of the Art"), so PRs opened against the old pins may now be behind master rather than ahead of it.

STEP 3, bring it up to date: `gh pr comment <n> --repo thezoid/ShopPyBot --body "@dependabot rebase"`, then poll `gh pr view <n> --repo thezoid/ShopPyBot --json mergeStateStatus,headRefOid --jq '{s: .mergeStateStatus, h: .headRefOid}'` every 30 seconds, maximum 30 iterations (15 minutes), until `CLEAN` or a changed head OID. Run the loop as a background Bash invocation; foreground `sleep` may be blocked.

STEP 3a, first timeout: record it, then try `gh pr update-branch <n> --repo thezoid/ShopPyBot` and poll a second 15-minute window.

STEP 3b, second timeout: record the Pitfall 5 pause evidence (comment URL, emoji reaction presence, unchanged head OID, both timestamps) in 36-CI-EVIDENCE.md, then fall through to STEP 5 if and only if the direction check now classifies it as superseded. If it is genuinely still a forward move and cannot rebase, STOP and escalate per 36-RESEARCH.md Assumption A2 (an operator Settings change, Phase 38 SCAN-01, not an autonomous retry).

STEP 4, merge: `timeout 1200 gh pr checks <n> --repo thezoid/ShopPyBot --watch --interval 30 > /dev/null 2>&1`, then `gh pr checks <n> --repo thezoid/ShopPyBot --json name,bucket`. Buckets `pass` and `skipping` satisfy protection. Then `gh pr merge <n> --repo thezoid/ShopPyBot --merge --delete-branch=false`. No `--admin`, no `--squash`, no `--rebase`. A `fail` bucket or `timeout` exit 124 is a STOP.

STEP 5, superseded-close: `gh pr close <n> --repo thezoid/ShopPyBot --delete-branch=false --comment "<reason>"`, the reason naming the action, the PR's target version, the version master carries, and the word Superseded, mirroring the PR #8 precedent.

STEP 6, record and re-verify: append one row to 36-MERGE-LOG.md, then after a MERGE run the ci.yml integrity re-check in task 1 before touching the next PR.
</dependabot_procedure>
