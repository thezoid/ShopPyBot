From core/captcha.py:
- Module constants: `_MAX_POLLS = 20`, `_INITIAL_WAIT_SECS = 15`, `_POLL_INTERVAL_SECS = 5`. Polling uses `time.sleep` (patch `core.captcha.time.sleep` to a no-op so tests are instant).
- `_poll_result(api_key, captcha_id)` (captcha.py:56-74): sleeps initial wait, then loops up to `_MAX_POLLS` GETs to `_RESULT_URL`. On `status == 1` returns the token. On a non-`CAPTCHA_NOT_READY` result, raises `RuntimeError("2captcha poll error: ...")` (line 72). After `_MAX_POLLS` iterations of CAPTCHA_NOT_READY, raises `TimeoutError("2captcha: exceeded max polls")` (line 74).
- `_check_balance(api_key)` (captcha.py:77-90): GET getbalance. `"ERROR_ZERO_BALANCE"` → 0.0; any other `text.startswith("ERROR_")` → raises `RuntimeError("2captcha balance check error: ...")` (line 89); else float(text).
- `CaptchaSolver.check_balance_at_startup()` (captcha.py:127-149): wraps `_check_balance`; on Exception logs WARNING using `exc.__class__.__name__` only and sets `self.balance_ok = False` (never logs `self._api_key`). On balance<=0 sets balance_ok False.
- `CaptchaSolver.solve_recaptcha(sitekey, pageurl)` (captcha.py:155-167): increments `self._solve_count` BEFORE network calls (so cap respected even on raise), calls `_submit_recaptcha` then `_poll_result`, on Exception logs `exc.__class__.__name__` and re-raises.
- `CaptchaSolver.solve_amazon_waf(key, iv, context, pageurl)` (captcha.py:169-203): raises RuntimeError if `can_solve()` is False; else increments `_solve_count`; POSTs AmazonTask to `_SUBMIT_URL`; on `body.get("status") != 1` raises `RuntimeError("2captcha AmazonTask submit error: ...")` (lines 195-196); else `_poll_result` then `json.loads(token_str)` (lines 198-201); on non-JSON token returns `{"captcha_voucher": token_str, "existing_token": ""}` (lines 202-203).
- Constructor: `CaptchaSolver(api_key, max_solves, low_threshold)`; `_solve_count` starts at 0; `balance_ok` starts True. `can_solve()` = `balance_ok and _solve_count < _max_solves`.
