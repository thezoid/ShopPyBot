<objective>
Wave 2: ship the contributor tooling (CORE-08) — `plugins/example_plugin.py` (a fictional "FakeShop" skeleton) and `plugins/PLUGIN_DEV.md` (the contributor guide) — so an external developer can copy the example, implement `check_availability` and `auto_buy`, and have a working plugin without reading any core source (success criterion 4).

The example is a complete, importable `RetailerPlugin` v2 subclass with heavy inline comments and a `# Replace ... with the real selector` marker. The guide covers: the `shopbot_plugin_*.py` naming/discovery rule, the ABC contract (required `check_availability`/`auto_buy` vs optional `login`/`detect_captcha`/`setup`/`teardown`), `domain_patterns` substring-matching semantics with a multi-domain example, config access (`self.config.platforms.*`, with the deferred-extensibility caveat), the env-vars-only credential rule, and how to run the test suite. It also carries the plugin-trust note (only install plugins you trust — full policy lands in Phase 3 DOCS-02/03).

This plan depends only on the ABC v2 (Plan 02); it shares no files with the registry (03), platform plugins (04), or main.py (05), so it runs in parallel within Wave 2.

Purpose: make the framework immediately usable by external contributors (the project's core value).
Output: `plugins/example_plugin.py`, `plugins/PLUGIN_DEV.md`, `tests/test_example_plugin.py`.
</objective>
