<objective>
Remove every blocking input() from the async path and replace the 5 Amazon
intervention sites with the asyncio.Event notify-and-wait pattern (ASYNC-03), and make
BestBuy/Amazon stop writing the DB directly so the orchestrator's write queue is the
sole write path (ASYNC-05 plugin side).

Purpose: input() blocks the entire event loop, stalling all other plugins. The locked
design replaces it with per-plugin asyncio.Events that the single stdin listener (Plan
03) sets; only the affected plugin pauses while others keep polling. Direct
update_item_purchased calls bypass the write-queue serialization, so they must be
removed.

Output: revised Amazon plugin with 4 Event attrs + a _wait_user_action helper at all 5
sites; BestBuy/Amazon auto_buy returning success without direct DB writes; a static
no-input() test; updated Amazon plugin unit tests.
</objective>

Event pattern (RESEARCH Target 3):
- In AmazonPlugin.__init__: create self.captcha_event, self.passkey_event,
  self.otp_event, self.test_pause_event = asyncio.Event() (safe pre-loop in 3.10+).
  Call super().__init__(config) first.
- Helper `async def _wait_user_action(self, event, message)`: play_notification_sound(),
  writeLog(message, "WARNING"), then `await asyncio.wait_for(event.wait(), timeout=300)`
  (5-min unattended guard) wrapped to catch asyncio.TimeoutError (log + continue), and
  `event.clear()` in finally (Pitfall 7 — always clear so next cycle re-waits).
- Replace each input(...) with `await self._wait_user_action(self.<event>, "<message>")`.
  Reuse test_pause_event for both test-mode sites.

DECISION (research Open Question 2): Event attributes live on AmazonPlugin ONLY, not on
the RetailerPlugin ABC. BestBuy has no input() sites and needs no events. Document this
in the SUMMARY. The stdin listener (Plan 03) already uses getattr(..., None) so plugins
lacking the attrs are skipped safely.

ASYNC-05 plugin side: the orchestrator's run_plugin (Plan 03) does
`await write_queue.put(link)` after a successful auto_buy. Therefore plugin auto_buy must
NOT call models.update_item_purchased directly. Currently amazon auto_buy calls it (line
~194) and bestbuy calls it (line ~163). Remove those direct calls; auto_buy returns True
on success and the orchestrator enqueues the write. Remove the now-unused
`from models import update_item_purchased` imports if nothing else uses them.

play_notification_sound is imported in amazon plugin already (utils). BestBuy currently
imports update_item_purchased — drop it after removing the call.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| human (browser intervention) -> plugin coroutine | User solves CAPTCHA/OTP in the visible browser, signals via Enter |
| plugin auto_buy -> write queue | Purchase success enqueued, not written directly |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-13 | Information Disclosure | intervention prompts | mitigate | _wait_user_action only logs a generic actionable message and awaits an Event; it never reads or echoes typed text. The user types into the browser, not into the bot; the bot only observes an Enter signal via the stdin listener. |
| T-04-14 | Denial of Service | indefinite block awaiting an Event when unattended | mitigate | asyncio.wait_for(event.wait(), timeout=300) bounds the wait; on timeout the plugin logs and continues rather than stalling forever |
| T-04-15 | Tampering | stale Event leaking across poll cycles | mitigate | event.clear() in the finally of _wait_user_action (Pitfall 7) so the next cycle genuinely re-waits |
| T-04-16 | Tampering | concurrent direct DB writes from plugins | mitigate | Direct update_item_purchased calls removed; all writes go through the single orchestrator write queue (ASYNC-05) |
</threat_model>
