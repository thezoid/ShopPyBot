**Gathered:** 2026-06-29

<domain>
## Phase Boundary

Close the three non-blocking integration warnings carried out of the v4.1 milestone
audit. All three live in `web/templates/dashboard.html` (frontend, vanilla JS, no
build step). No new observability surface, no new endpoint, no server behavior change
except where the chosen fixes are purely client-side. Scope is exactly three fixes:

1. **SSE stall fallback** (Warn 3 / SSE-01/02) — EventSource `onerror` fires only on
   close, never on idle. If the stream stays open but the server stops sending `status`
   frames, `#sse-indicator` stays "Live" while data goes stale. Add a client-side
   safety net.
2. **uPlot load order** (Warn 1 / OBS-05) — `<script src="uplot.iife.min.js">` loads at
   end of `<body>`, after the inline block that calls `new uPlot()`. Cold-load race.
3. **Log duplicate guard** (Warn 2 / OBS-07) — `appendLogLine`'s `_lastLogLine`
   content-equality check drops ALL consecutive identical lines, suppressing
   legitimately repeated bot messages, not just the one backfill→SSE boundary dupe.

Out of scope: 13 deferred live-UAT items (operator checklist), UI-03 dead remove-button
handler (separate warning, not named in this phase), Nyquist doc flips (already closed in
recent commits).

<decisions>
## Implementation Decisions

### SSE Stall Detection & Fallback (SSE-01/02)
- Detection: client-side idle watchdog tracking the timestamp of the last received
  `status` SSE event. Server emits a `status` frame every 1s unconditionally
  (`web/sse_hub.py:_POLL_INTERVAL_SECS = 1.0`), so any multi-second gap is a real stall.
- Stall threshold: 8 seconds with no `status` event (8 missed 1s ticks; comfortably
  under the 15s keepalive and above normal jitter).
- Action on stall: flip `setIndicator('reconnecting')` AND start a REST polling safety
  net — periodic `pollStatus()` + `pollLogs()` at `POLL_MS` (2000ms) — so data keeps
  refreshing while SSE is silent. This is the actual safety net, not just a visual cue.
- Recovery: on the next `status` SSE event, stop the fallback polling interval, reset the
  watchdog timer, and `setIndicator('live')`. No N-consecutive-event gate.
- Do NOT force `es.close()`+reopen: if the server-side `_poll_loop` died there is no
  producer to reconnect to; REST polling is the resilient path.

### Log Duplicate Guard (OBS-07)
- Replace the blanket content-equality drop with a one-shot boundary dedup: a line is
  dropped only if it equals the last backfilled line AND it is the first SSE line
  after a repaint.
- Mechanism: a `_dedupNextLine` boolean flag set true after `renderLogLines` finishes a
  backfill; the first subsequent `appendLogLine` consumes it (drops if matching, then
  clears the flag); all later lines append unconditionally.
- Legitimately repeated consecutive bot messages are always shown (no suppression, no
  "(×N)" collapsing).
- Empty-filter repaint resets both `_lastLogLine` and the `_dedupNextLine` flag.

### uPlot Load Order (OBS-05)
- Move `<script src="/static/vendor/uplot.iife.min.js">` from end of `<body>` (line 894)
  to the end of `<head>` (after the CSS links, before `</head>`), so the `uPlot` global
  is defined before the inline block's `new uPlot()` can run at cold load with no warm
  cache.
- The uPlot CSS `<link>` (head, line 20) stays unchanged.
- Hard constraint preserved: stay vendored, zero-Node, no CDN, no bundler.

### Claude's Discretion
- Exact watchdog implementation (setInterval vs setTimeout reset), variable naming, and
  test structure are at Claude's discretion, consistent with existing dashboard.html
  conventions (IIFE helpers, pure render functions, `CR-`/`WR-`/`OBS-` comment tags).

</decisions>

## Existing Code Insights

### Reusable Assets
- `setIndicator(state)` (dashboard.html:347) already toggles Live/Reconnecting — reuse
  for both stall and recovery; no new indicator code needed.
- `pollStatus()` (359) and `pollLogs()` (562) are the existing REST one-shot fetchers —
  reuse directly as the fallback safety net (already used for initial backfill at 598-599
  and as the no-EventSource fallback at 613-614).
- `renderStatus`/`renderHealthCards`/`renderUptime` are pure renderers shared by both the
  poll and SSE paths — fallback polling reuses them with no change.
- `appendLogLine` (500) and `renderLogLines` (522) are the only two writers of the log
  buffer; `_lastLogLine` and the 500-line cap live here.

### Established Patterns
- All client code is vanilla JS in one inline `<script>` (190-893); helpers wrapped in
  IIFEs; constants like `POLL_MS = 2000` (208) and `MAX_LOG_LINES = 500` (323) declared
  at top of scope.
- SSE wiring block at 601-615: `EventSource('/api/events')`, named-event listeners
  (`status`, `log`) with try/catch JSON.parse (CR-01), `onopen`→live, `onerror`→reconnecting.
- Server contract: `web/sse_hub.py` `_poll_loop` broadcasts `status` every 1s + a `log`
  frame per new line; `web/routes/sse.py` keepalive comment at 15s idle.

### Integration Points
- Stall watchdog hooks the existing `status` listener (604-606): record a timestamp there.
- Fallback polling reuses the same `setInterval(pollStatus/pollLogs, POLL_MS)` shape as the
  no-EventSource branch (613-614) — start on stall, `clearInterval` on recovery.
- uPlot move is a one-line relocation of the `<script>` tag (894 → before `</head>` at 21).
- Tests: `tests/test_sse_wiring.py` holds the 8 wiring assertions (incl.
  `test_no_onmessage_for_named_events`); new watchdog/dedup/load-order assertions extend it.
