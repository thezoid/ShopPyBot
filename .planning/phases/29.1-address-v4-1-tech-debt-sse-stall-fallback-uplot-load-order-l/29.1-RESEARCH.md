## User Constraints (from CONTEXT.md)

### Locked Decisions

**SSE Stall Detection and Fallback (SSE-01/02)**
- Detection: client-side idle watchdog tracking the timestamp of the last received
  `status` SSE event. Server emits a `status` frame every 1s unconditionally
  (`web/sse_hub.py:_POLL_INTERVAL_SECS = 1.0`), so any multi-second gap is a real stall.
- Stall threshold: 8 seconds with no `status` event (8 missed 1s ticks; comfortably
  under the 15s keepalive and above normal jitter).
- Action on stall: flip `setIndicator('reconnecting')` AND start a REST polling safety
  net — periodic `pollStatus()` + `pollLogs()` at `POLL_MS` (2000ms) — so data keeps
  refreshing while SSE is silent. This is the actual safety net, not just a visual cue.
- Recovery: on the next `status` SSE event, stop the fallback polling interval, reset the
  watchdog timer, and `setIndicator('live')`. No N-consecutive-event gate.
- Do NOT force `es.close()`+reopen.

**Log Duplicate Guard (OBS-07)**
- Replace the blanket content-equality drop with a one-shot boundary dedup.
- Mechanism: a `_dedupNextLine` boolean flag set true after `renderLogLines` finishes a
  backfill; the first subsequent `appendLogLine` consumes it (drops if matching, then
  clears the flag); all later lines append unconditionally.
- Legitimately repeated consecutive bot messages are always shown.
- Empty-filter repaint resets both `_lastLogLine` and the `_dedupNextLine` flag.

**uPlot Load Order (OBS-05)**

### Pattern 1: One-Shot Flag for Boundary Dedup

**What:** A boolean flag is set by a producer (`renderLogLines`) after completing a
batch write. The next consumer call (`appendLogLine`) reads and clears the flag in its
first invocation, then operates normally for all subsequent calls.

**When to use:** When the boundary between two sequential producers must be detected
exactly once without tracking call counts or timestamps.

**Example (inline JS, no transpilation needed):**

```javascript
// Source: CONTEXT.md decision / dashboard.html conventions
var _dedupNextLine = false;

function producer() {
  // ... batch write ...
  _dedupNextLine = true;  // arm for next consumer call
}

function consumer(line) {
  if (_dedupNextLine) {
    _dedupNextLine = false;           // always clear on first call
    if (line === _lastLine) return;   // drop only if it matches
  }
  // unconditional processing for all subsequent calls
}
```

### Pattern 2: Nested setInterval for Conditional Fallback

**What:** An outer watchdog `setInterval` checks a staleness condition periodically.
When the condition is true it starts an inner `setInterval` (the actual fallback work).
When the condition clears, `clearInterval` stops the inner timer. The outer watchdog
continues running.

**When to use:** When a primary channel (SSE) should degrade gracefully to a secondary
channel (REST polling) on inactivity, without closing the primary.

```javascript
// Source: CONTEXT.md decision; matches existing POLL_MS / setInterval shape
var _fallbackTimer = null;
var _watchdog = setInterval(function() {
  if (isStale()) {
    if (!_fallbackTimer) _fallbackTimer = setInterval(doFallback, POLL_MS);
  }
}, POLL_MS);

// In the recovery path:
clearInterval(_fallbackTimer);
_fallbackTimer = null;
```

### Anti-Patterns to Avoid

- **Blanket consecutive-equality drop in appendLogLine:** Suppresses legitimate repeated
  bot messages (e.g., "Bot loop tick" logged every iteration). Fixed by the one-shot
  flag; do not revert to the old guard.
- **`es.close()` + reopen on stall:** If `_poll_loop` is dead, there is no producer to
  reconnect to; the stream would reopen to silence. REST polling is the resilient path.
- **`defer` on the uPlot `<script src>`:** The inline block runs synchronously during
  HTML parsing; a `defer`red external script executes at `DOMContentLoaded`, which may
  be after the inline block has already run. Moving to `<head>` without `defer` is the
  unambiguous fix.
- **Placing `_dedupNextLine = true` inside the empty-lines branch of renderLogLines:**
  If `lines.length === 0`, the function creates a "no results" `<p>` and returns early.
  The flag must NOT be armed in the empty path (no SSE line could match nothing). Arm
  only after a non-empty batch completes.

## Common Pitfalls

### Pitfall 1: Empty-Filter repaint arms `_dedupNextLine` incorrectly

**What goes wrong:** `renderLogLines([])` creates a "No log lines match" placeholder and
returns early (line 527-533). If `_dedupNextLine = true` is placed outside the early-return
guard (e.g., after the `forEach` on line 534), it would be unreachable for the empty case
and the flag would be left in its prior state. If the prior state was `true` and the next
SSE line matches `_lastLogLine`, it would be incorrectly dropped.

**Why it happens:** The `lines.forEach` loop and the early-return path share the same
function but the arming statement must be conditional on a non-empty backfill.

**How to avoid:** Place `_dedupNextLine = true` inside the non-empty path only (after the
`forEach` call, before `maybeScrollToBottom()`). Keep `_dedupNextLine = false` reset at the
top of `renderLogLines` (before the early-return check) so ALL paths (empty and non-empty)
clear the flag first.

**Warning signs:** First SSE line after a filter change with zero results gets dropped.

### Pitfall 2: Watchdog fires before the first `status` event on a fresh page load

**What goes wrong:** `_sseLastStatusTs` is initialized to `Date.now()` at EventSource
construction time. If the server takes more than `SSE_STALL_MS` (8s) to emit the first
`status` frame (e.g., slow network), the watchdog fires before any event arrives and
starts fallback polling unnecessarily.

**Why it happens:** The watchdog tick interval starts at construction; `_poll_loop` has a
1s delay before its first `await asyncio.sleep(interval)`, so the first `status` frame
arrives ~1s after EventSource opens. In practice this is not a problem since 1s << 8s,
but it must be initialized correctly.

**How to avoid:** Initialize `_sseLastStatusTs = Date.now()` at construction (not at
`onopen`), and also reset it in `onopen` for clean reconnects. The 8s threshold gives
plenty of room over the expected ~1s first-frame latency.

**Warning signs:** `#sse-indicator` shows "Reconnecting" briefly on every fresh page load.

### Pitfall 3: `_sseFallbackTimer` not guarded with `if (!_sseFallbackTimer)` check

**What goes wrong:** If the watchdog ticks multiple times after a stall, each tick
starts an additional `setInterval` for fallback polling. Multiple concurrent polling
intervals hit `/api/status` and `/api/logs` at compounding rates.

**Why it happens:** `setInterval` always returns a new timer handle; calling it again
does not replace the old one.

**How to avoid:** Guard the inner `setInterval` call with `if (!_sseFallbackTimer)`.

**Warning signs:** Network tab shows duplicate `/api/status` requests firing in lock-step.

### Pitfall 4: `_lastLogLine` not reset before `_dedupNextLine = true` is armed

**What goes wrong:** If `renderLogLines` is called with a non-empty batch but `_lastLogLine`
still holds the value from a previous repaint, the first SSE line after the new backfill
could be incorrectly dropped if it happens to match the old value.

**Why it happens:** `_lastLogLine` is reset to `''` at the top of `renderLogLines` (existing
line 525), then updated by each `appendLogLine` call in the `forEach`. After the forEach,
`_lastLogLine` holds the last line of the current backfill. This is correct — `_dedupNextLine`
arms AFTER the forEach, so `_lastLogLine` is already the right value to compare against.

**How to avoid:** Maintain the existing order: reset `_lastLogLine = ''` at top, run
`forEach`, then arm `_dedupNextLine = true`. Do not change the reset position.

**Warning signs:** First SSE log line after any filter change is mysteriously absent.

### Pitfall 5: uPlot `<script>` moved with `defer` instead of synchronously

**What goes wrong:** Adding `defer` to `<script src="uplot.iife.min.js">` in `<head>`
defers execution to after HTML parsing. The inline `<script>` block at line 190 runs
synchronously during parsing. If `loadItems()` is called at line 889 and ultimately
calls `new uPlot()` via `loadPriceChart()` at line 481 before `DOMContentLoaded`, the
deferred script has not yet run, reproducing the original `ReferenceError`.

**How to avoid:** Do NOT add `defer`. Move the `<script src>` to `<head>` as a
synchronous (blocking) load. This is intentional: the small ~52KB file loads before
the HTML body parses, guaranteeing `uPlot` is defined before any inline script runs.

**Warning signs:** Cold-load chart rendering throws `ReferenceError: uPlot is not defined`
in the browser console even after the move.

### Pitfall 6: SSE_STALL_MS constant placed inside the `if (typeof EventSource)` block

**What goes wrong:** If `SSE_STALL_MS` is declared inside the `if` block rather than at
module top-level, it is not grep-searchable from tests using simple text assertions on the
rendered page (the test would need to know the block structure).

**How to avoid:** Declare `SSE_STALL_MS` at the top of the inline script scope, adjacent
to `POLL_MS` (line 208), consistent with `MAX_LOG_LINES` (line 323) — all named constants
are top-level for discoverability.

**Regression risk on `test_setinterval_only_in_fallback`:** This test (lines 170-227 of
`test_sse_wiring.py`) specifically checks that `setInterval(pollStatus` and
`setInterval(pollLogs` appear only AFTER the `else` branch of `typeof EventSource`.
Fix 3 introduces a nested `setInterval` inside the `if` branch that calls `pollStatus()`
and `pollLogs()` — but NOT as bare `setInterval(pollStatus, ...)` calls; they are wrapped
in an anonymous function: `setInterval(function() { pollStatus(); pollLogs(); }, POLL_MS)`.

The test searches for literal strings `"setInterval(pollStatus"` and `"setInterval(pollLogs"`.
If the fallback inner timer is written as `setInterval(pollStatus, POLL_MS)`, the test WILL
FAIL. If it is written as `setInterval(function() { pollStatus(); pollLogs(); }, POLL_MS)`,
the test stays GREEN. The planner MUST use the anonymous-function wrapper shape.
