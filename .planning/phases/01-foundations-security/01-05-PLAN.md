## SEC-04 Phase-1 decision (explicit — do NOT defer)

RESEARCH argues nodriver makes `navigator.webdriver` undefined by architecture, so "no CDP patch needed." BUT nodriver is NOT instantiated in Phase 1 — the bot still runs the existing **Selenium** ChromeDriver in main.py (nodriver migration is Phase 2). A Selenium-launched Chrome DOES expose `navigator.webdriver === true`. Leaving it leaking until Phase 2 violates SEC-04. **Decision: in Phase 1, satisfy SEC-04 on the existing Selenium driver** by calling `driver.execute_cdp_cmd("Page.addScriptToEvaluateOnNewDocument", {"source": "Object.defineProperty(navigator,'webdriver',{get:()=>undefined})"})` immediately after the driver is created, before any `driver.get()`. This is the verified Selenium CDP idiom. When Phase 2 swaps in nodriver, this CDP call is removed (nodriver handles it architecturally). The decision is recorded here and in a code comment in main.py.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| environment / getpass → process memory | Credentials and CVV enter only at runtime, held in memory |
| retailer site → Selenium driver | Anti-bot fingerprinting; driver must not advertise automation |
| process → log files / stdout | Logs must never contain credentials or CVV |
| process → on-disk config | config.yml must never hold secrets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-WD | Spoofing | navigator.webdriver leak on Selenium driver | mitigate | SEC-04: CDP Page.addScriptToEvaluateOnNewDocument sets navigator.webdriver to undefined at startup before any navigation. Explicit Phase-1 decision (nodriver replaces this in Phase 2). |
| T-01-DWS | Spoofing | --disable-web-security fingerprint | mitigate | SEC-03: flag removed; real Chrome UA set (SEC-05). |
| T-01-CVV | Information Disclosure | CVV on disk or in logs | mitigate | SEC-02: getpass.getpass (no echo) at runtime; never written to config, file, or logger. Non-interactive terminals SystemExit rather than echo (RESEARCH Pitfall 4). |
| T-01-ENV | Information Disclosure | credentials in config.yml | mitigate | SEC-01: email/password read only from os.environ; sample.config.yml credential block removed; .env.example documents env vars; .env expected gitignored. |
| T-01-STDERR | Tampering | sys.stdout devnull hiding driver init exceptions | mitigate | INFRA-03: removed; Service(log_output=subprocess.DEVNULL) suppresses only ChromeDriver subprocess output, leaving Python exceptions visible. |
| T-01-LOGLEAK | Information Disclosure | credential/CVV passed to writeLog | mitigate | Code review + acceptance check: no credential or CVV variable is ever an argument to writeLog. |
</threat_model>
