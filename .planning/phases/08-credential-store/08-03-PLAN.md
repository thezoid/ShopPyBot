<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cfg.credentials.backend → _build_store | Config-driven backend choice; must not allow a secret to flow into config |
| init_store → writeLog | Startup logging boundary; only the backend name may cross |
| SHOPBOT_STORE_PASSPHRASE → _resolve_passphrase | Passphrase enters memory only, never disk/log |
| secrets → disk sinks (config.yml/logs/SQLite) | Must remain plaintext-free at rest |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-09 | Information Disclosure | startup backend logging leaks a secret | mitigate | writeLog emits only the backend label; test_startup_log_backend_name + grep gate assert no secret value (Task 1) |
| T-08-10 | Information Disclosure | secret value written plaintext to config.yml/logs/SQLite | mitigate | tests/test_no_plaintext.py scans all three sinks for every SECRET_KEYS value (Task 3) |
| T-08-11 | Spoofing | auto-detect picks null/fail keyring and silently loses secrets | mitigate | _build_store auto path uses _has_real_keyring() before choosing keyring (Task 1) |
| T-08-12 | Denial of Service | getpass blocks the asyncio event loop | mitigate | passphrase resolved at init time (before thread/loop start) via SHOPBOT_STORE_PASSPHRASE; getpass never called inside async (Task 1, Pitfall 3) |
</threat_model>
