<objective>
Wire the notification system into the running bot: build the dispatcher from config at startup,
gate notifications on the dedup rising edge inside the poll loop, and extend the Phase-4 write
queue to handle the three typed dedup/purchase ops. Close with a human-verify checkpoint for
live Discord delivery.

Purpose: This is the integration that makes NOTIF-01/02/04 observable end-to-end. The
orchestrator replaces its direct `play_available_sound()` / `play_buy_sound()` calls with
`dispatcher.notify(event)`, gated so a notification fires only on the unavailable->available
transition (NOTIF-02), and routes the resulting dedup state writes through the existing
serializing write queue (no `database is locked` regression).

Output: a `build_dispatcher(cfg)` factory in notifications/__init__.py; orchestrator changes
(dispatcher param threaded through async_main -> run_plugin -> _check_and_buy, the edge-trigger
logic, and the extended write-queue drain handling typed tuples); orchestrator tests; and a
blocking human-verify checkpoint for live Discord.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config -> build_dispatcher | enable flags decide which network channels are constructed |
| poll coroutine -> write queue -> SQLite | all dedup/purchase writes serialized through the single queue |
| live run -> logs/ | a misconfigured channel must produce a scrubbed log, never a secret |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-14 | Denial of Service | dedup bypass flooding channels | mitigate | Notify gated on the 0->1 rising edge via get_item_notification_state_sync; suppressed while available (NOTIF-02 / Pitfall 3) |
| T-05-15 | Tampering | concurrent dedup writes -> database is locked | mitigate | set_available/clear_available/purchased all routed through the single write-queue drain (Pitfall 6); no direct sync write from poll coroutines |
| T-05-16 | Information Disclosure | live-run log leakage | mitigate | Human-verify step 6 inspects logs/ for any webhook URL substring; dispatcher + notifiers log class+status only |
| T-05-17 | Information Disclosure | newline/URL injection into embed | accept | Event fields are internally generated from DB items, not user input; Discord embeds JSON-encode field values |
</threat_model>
