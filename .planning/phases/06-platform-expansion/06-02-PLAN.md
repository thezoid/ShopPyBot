<objective>
Wire ANTI-01 per-platform jitter into the orchestrator. Replace the fixed poll_interval sleep in
run_plugin with a per-plugin random.uniform(min_delay, max_delay) read from the plugin's platform
config, falling back to the shared poll_interval when the platform config does not define both fields.

Purpose: SC2 requires that setting walmart min_delay=8/max_delay=15 in config.yml changes polling
interval behavior with NO code change -- the jitter must read config at runtime. This plan owns the
orchestrator change and establishes the platform_key lookup convention the five plugins rely on.
Output: a _get_plugin_sleep helper, a one-line run_plugin change, and ANTI-01 unit tests.
</objective>

  min_delay: float, max_delay: float, headless: bool, user_agents: list[str].
- amazon/bestbuy submodels do NOT have min_delay/max_delay (they have delay_seconds/delay_jitter).

Convention this plan establishes (Claude's Discretion per CONTEXT.md, RESEARCH Pattern 2 recommendation):
- Each new plugin class declares `platform_key: str` matching its config attribute name
  (e.g. "walmart"). _get_plugin_sleep reads getattr(plugin, "platform_key", None) and looks up
  getattr(plugin.config.platforms, platform_key, None). This avoids fragile class-name string munging.
