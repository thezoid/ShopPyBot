**Tooling notes for every task in this plan:**

1. **`rtk git status --porcelain` prints the 4-byte string `ok` on a clean tree.** Measured
   directly on this box, rtk 0.37.2, reproduced against both this repo and a scratch repo: where
   raw git prints nothing, rtk prints `ok`, which is non-empty and truthy. Every emptiness test in
   this plan therefore uses **`rtk proxy git status --porcelain`**, which is verified byte-identical
   to raw git. Do not "simplify" those call sites back to `rtk git status`; an emptiness test
   against the filtered form can never pass and inverts the guard it belongs to.
2. `rtk git log` drops merge commits and caps output at 50, and returns EMPTY for an all-merge
   range, which reads as "in sync". Use `rtk proxy git log` for every range or audit query.
   `rtk git diff` reformats its output (stat header, a literal `--- Changes ---` separator,
   two-space-indented hunk lines), so never line-count or pattern-match it; use
   `rtk proxy git diff`. `git rev-list --count` and `git merge-base --is-ancestor` are accurate
   through rtk and need no workaround.
3. All GitHub API calls are written as plain `gh api`, except where an HTTP status line is the
   assertion, which requires `rtk proxy gh api -i` so the raw first line survives. If any response
   looks summarised or truncated, re-run with `rtk proxy gh api ...` and use the raw JSON. Never
   accept a filtered body as evidence for an acceptance criterion.
4. POSIX BRE only. `rg` and `grep -oP` are unavailable. `grep -E`, `sed`, `sort`, `comm`, `diff`
   and `awk` are all present and verified. Use `python -c` for JSON work that `--jq` makes awkward.
5. The repo owner/name is `thezoid/ShopPyBot`. Write it literally. The `:owner/:repo` placeholders
   only expand when the shell cwd is inside the git repo, and they fail silently otherwise.
6. **Fenced blocks marked ONE INVOCATION are contracts, not formatting.** Shell variables do not
   survive between invocations, and a guard that exits in an earlier invocation cannot stop a
   command submitted in a later one. Every such block opens with `set -e`, asserts on VALUES read
   back inside that same block, and exits non-zero rather than warning. Do not unwrap them, do not
   run their lines individually, and do not split a guard from the thing it guards.
