<objective>
Empty the code scanning queue of everything that is not a real finding, one alert at a time with a
stated reason, and turn on the two secret scanning options that are currently off.

Purpose: a queue full of known-benign findings is a queue nobody reads, which is how a real finding
gets missed. The fix is per-alert dismissal with a specific reason, not a path filter. A
`paths-ignore` on `tests/` would clear the same 19 alerts today and would also hide every future
finding in those files, including a real one. That trade is not acceptable and this plan does not
make it.

Output: 26 dismissed alerts with recorded reasons, two repository settings enabled, and the
evidence for each re-queried from the API.

This plan changes no source files. Every action is a GitHub API mutation followed by a re-query.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dismissal reason to future reader | A dismissal is a durable claim that a finding is not real. A wrong or vague reason silently converts a real vulnerability into an accepted one |
| Per-alert dismissal versus path filter | A path filter also hides future findings in the same files. A per-alert dismissal does not |
| Validity checks to external providers | Enabling validity checks means candidate secrets are sent to issuing providers for a liveness answer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-24 | Repudiation | Dismissal of alerts 6 through 24 | mitigate | Reason `used in tests` with a comment naming the specific mechanism, plus a mandatory spot check of two alerts confirming the URL literal is defined in the same file. Any alert taking external input is excluded and reported |
| T-38-25 | Information Disclosure | Dismissal of the 7 clear-text alerts | mitigate | Three distinct reason strings, one per sub-case, each naming the taint source at `core/credentials.py:47`. Gated on `tests/test_secret_names_not_values.py` being on master and passing, so the claim is enforced rather than asserted |
| T-38-26 | Repudiation | Blanket suppression | mitigate | Task 1 forbids `paths-ignore`, a CodeQL config file, and `lgtm` or `nosec` comments, and the acceptance criteria grep for all three |
| T-38-27 | Repudiation | Staleness claim for alerts 25 and 26 | mitigate | The claim is checked with the `/instances` endpoint before it is written into the dismissal comment. If any open instance carries a live analysis category, the alert is reclassified |
| T-38-28 | Information Disclosure | Newly surfaced secret scanning alerts | mitigate | Task 3 explicitly forbids dismissing a new alert to preserve a zero count and requires reporting live credentials as a blocking operator finding |
| T-38-29 | Information Disclosure | Validity checks calling out to providers | accept | This is exactly what SCAN-09 asks for and the alternative is not knowing whether a leaked credential is live. Recorded as a new outbound interaction so the change is visible |
