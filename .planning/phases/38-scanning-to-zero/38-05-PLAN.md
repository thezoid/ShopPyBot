<objective>
Empty the code scanning queue of everything that is not a real finding, one alert at a time with a
stated reason, and turn on the two secret scanning options that are currently off.

Purpose: a queue full of known-benign findings is a queue nobody reads, which is how a real finding
gets missed. The fix is per-alert dismissal with a specific reason, not a path filter. A
`paths-ignore` on `tests/` would clear the same 19 alerts today and would also hide every future
finding in those files, including a real one. That trade is not acceptable and this plan does not
make it.

Output: 26 dismissed alerts with recorded reasons, two repository settings enabled, and the
evidence for each re-queried from the API. That is 26 of the 31 open code scanning alerts. The
other 5 were fixed in source by earlier plans of this phase, not dismissed: `#3`, `#4`, and `#5`
via `core/urls.host_matches` in SCAN-03, and `#33` and `#34` via workflow permissions in SCAN-05.
Whether those 5 actually leave the queue is not this plan's to claim: code scanning default setup
reads `languages: []` and `updated_at: null`, so no analysis has run on master since 2026-08-06 at
`bd70601` and their `open` state is a property of that frozen snapshot rather than of master's
tree. This plan therefore reports three routes, not one number: 26 dismissed with a per-alert
reason, 5 fixed in source and NOT RE-ANALYSED, and 0 suppressed. It does not dismiss the 5 to
reach a zero, and it does not report a zero it did not produce.

This plan changes no source files. Every action is a GitHub API mutation followed by a re-query.

Every command in this plan is POSIX shell, run under Git Bash, which is the shell the operator
uses. There is no PowerShell anywhere in it and none may be added. Every guard asserts on a VALUE
and exits `1`, and every guard lives in the SAME fenced block, submitted as ONE invocation, as the
mutation it guards. Shell variables do not survive between invocations, so a block that consumes a
derived value re-derives it rather than trusting an earlier block's variable to still exist. State
that genuinely has to cross an invocation boundary is written to a FILE and re-read with a value
assertion, never left in a variable.

   ```
   ALERT #<n> ROTATED-OR-BENIGN: <what it is, where, and why sending it to its provider is acceptable>
   ```
   One `ALERT #<n>` line per open alert. A live credential is cleared only AFTER rotation, and the
   line says so. Writing this file to make a guard pass, without doing the reading it attests to, is
   the failure this whole task is built to prevent.
