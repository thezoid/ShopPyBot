<objective>
Land the branch on master and then prove, from the API rather than from the diff, that the code
changes actually closed the alerts they were written to close.

Purpose: the phase's verification bar is that a finding counts as resolved only when the alert
state is closed or dismissed and re-queried after the change. A merged diff that looks correct
proves nothing. This plan is also the first live test of the SHA pins and the permissions block:
a bad pin produces a startup failure with zero jobs scheduled, which fails the required checks and
blocks the merge instead of landing quietly.

Output: master carrying every file change from 38-02 and 38-03, and a summary holding the
before-and-after API state for alerts 3, 4, 5, 33, 34 and Dependabot 13.

This plan changes no files. Direct pushes to master are not authorised; the change reaches master
through a pull request.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pull request branch to master | This is the only authorised path for a change to reach the default branch. Direct push is not authorised |
| Diff to alert state | A merged change is a claim. The alert API is the evidence. These are different things and the phase's verification bar depends on not confusing them |
| Third-party action to runner | First live execution of the SHA pins from 38-03 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-19 | Repudiation | "Resolved" claims for alerts 3, 4, 5, 33, 34 | mitigate | Task 2 re-queries each alert by number after confirming an analysis exists for the merged SHA. A per-number query 404s or returns state, where a filtered list query can silently omit |
| T-38-20 | Denial of Service | `CodeQL` required context | mitigate | Task 1 stops before merging if `CodeQL` is absent from the check list, treating it as the SCAN-06 trap firing rather than as a transient |
| T-38-21 | Tampering | SHA-pinned actions, first execution | mitigate | Task 1 treats `startup_failure` with zero steps as an unresolved or disallowed action reference and explicitly forbids reverting to a floating tag to make the check pass |
| T-38-22 | Repudiation | Dependabot alert 13 disposition | mitigate | Task 3 forbids dismissing a genuinely-fixed alert as `inaccurate` or `not_used`, requires `fix_started` with the master SHA in the comment, and only after a bounded wait and a remote manifest read |
| T-38-23 | Information Disclosure | Pull request body | accept | The body names alert numbers and rule ids, all of which are already visible in the public security tab of a public repository. No secret material is added |
</threat_model>
