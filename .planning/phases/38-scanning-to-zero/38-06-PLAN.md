The sequence below is a hard ordering. Every step must pass before the next runs. If any step
fails, stop with the branch intact. A deleted branch whose commit was never tagged is unrecoverable
once GitHub garbage-collects the unreferenced object.

**Step 1, re-measure. Do not trust the planning-time SHA.**
```
git fetch origin --prune --tags
DEVSHA=$(gh api repos/thezoid/ShopPyBot/branches/dev --jq .commit.sha)
echo "$DEVSHA"
git rev-list --count "origin/master..$DEVSHA"
git rev-list --count "$DEVSHA..origin/master"
git merge-base --is-ancestor "$DEVSHA" origin/master; echo "ancestor_exit=$?"
```
Expected: `DEVSHA` is `65ef2b906ed4b6aca85ccf4e02e42deff80174e3`; ahead count `1`; behind count
around `923`; `ancestor_exit` NONZERO. A nonzero ancestor exit is the proof that the commit is not
reachable from master, which is the entire reason the tag is required. If `ancestor_exit` is `0`,
the commit is already on master, the archive tag is unnecessary, and that changes the disposition:
record it and delete the branch without the tag, noting why.

If `DEVSHA` differs from the planning-time value, stop and report. Someone pushed to a branch that
has been dormant for 17 months and that needs a human look.

**Step 2, create the tag on the remote.**
```
gh api -X POST repos/thezoid/ShopPyBot/git/refs -f ref=refs/tags/archive/dev-final -f sha="$DEVSHA"
```
A lightweight tag is sufficient. It is a ref pointing at the commit, which is exactly what keeps
the object alive.

**Step 3, verify the tag before touching the branch. All four checks must pass.**
```
gh api repos/thezoid/ShopPyBot/git/ref/tags/archive/dev-final --jq '"type=\(.object.type) sha=\(.object.sha)"'
git fetch origin "refs/tags/archive/dev-final:refs/tags/archive/dev-final" --no-tags
git rev-parse archive/dev-final
git cat-file -t "$DEVSHA"
```
Required results:
  a. The API returns `sha` equal to `$DEVSHA`.
  b. The fetch succeeds, proving the tag is reachable from a clean clone and not merely an API
     artifact.
  c. `git rev-parse archive/dev-final` prints `$DEVSHA`.
  d. `git cat-file -t "$DEVSHA"` prints `commit`, proving the object is present locally.

If any of a through d fails, STOP. The branch stays.

**Step 4, only now, delete the branch.**
```
gh api -X DELETE repos/thezoid/ShopPyBot/git/refs/heads/dev
```

**Step 5, re-query both sides.**
```
gh api repos/thezoid/ShopPyBot/branches/dev; echo "branch_query_exit=$?"
gh api repos/thezoid/ShopPyBot/git/ref/tags/archive/dev-final --jq '.object.sha'
git fetch origin --prune
git ls-remote origin "refs/heads/dev" "refs/tags/archive/dev-final"
```
Required: the branch query fails with 404; the tag still resolves to `$DEVSHA`; `git ls-remote`
lists the tag ref and lists no `refs/heads/dev`.

**Step 6, record it.** Append a `## SCAN-10 RESOLVED` section to `38-SCAN-BASELINE.md` holding the
archived SHA, the tag name, the ahead and behind counts, the `ancestor_exit` value, and the four
tag verification outputs. Note that the 4 workflows the branch carried
(`app_linuxBuild.yml`, `app_macBuild.yml`, `app_windowsBuild.yml`, `codeql-analysis.yml`) are
preserved inside the tagged tree and are no longer reachable from any branch, and that the Actions
workflow list may keep showing stale disabled entries for a while, which is cosmetic and not a
finding.

Do not edit `.github/workflows/ci.yml` or `gitleaks.yml` to drop `dev` from their branch filters.
That non-change was decided and recorded in 38-03 Task 1.
