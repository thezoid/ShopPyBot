# BLOCKING CONSTRAINTS — Read Before Anything Else

> Each was discovered through actual failure in this session, not predicted.
> Acknowledge each explicitly before proceeding.

- [ ] CONSTRAINT: a bare top-level `throw` in PowerShell does NOT stop a command submitted after it across a call boundary — reproduced on this box: the guard prints its refusal and the `git rm` / `-X DELETE` on the following line still runs, then the block exits clean — every guard-plus-mutation block must be wrapped in `& { ... }` so the guard and the mutation are ONE parsed unit, and an automated driver must abort the whole sequence on the opening-brace parse error rather than logging it and continuing
- [ ] CONSTRAINT: shell variables do NOT persist between separate harness command calls — an empty `$DEVSHA` made `git rev-list --count "origin/master..$DEVSHA"` silently degrade to `origin/master..HEAD` and exit 0, and the plan read that exit 0 as its proof the branch was safe to delete — any multi-step proof must run in ONE invocation, and any guard must be a value check plus `throw`, never an exit-code check
- [ ] CONSTRAINT: `rtk git log` is lossy — drops ALL merge commits and caps at 50, returning EMPTY for a range whose commits are all merges — use `rtk proxy git log` for any range, audit, or completeness query; `rtk git rev-list --count` and `rtk git merge-base --is-ancestor` are verified accurate
- [ ] CONSTRAINT: `rtk git diff` reformats output (stat header, a literal `--- Changes ---` separator, two-space-indented hunks) — never pattern-match or line-count its output; use `rtk proxy git diff` whenever the output feeds an acceptance criterion
- [ ] CONSTRAINT: the Phase 38 execution gate has returned FAIL TWICE and run 3 was stopped before returning a verdict — the plans are formally unverified — do not execute any plan until a gate run finishes with a written PASS

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Guard that cannot stop what follows it | A `throw` guard placed above a destructive command only terminates its own statement when the two are submitted separately. Measured: verdict `DEFER`, guard printed "DO NOT DELETE", `git rm` ran anyway. Same defect found independently at two sites, plus a third block that had only prose protection. | blocking | Wrap guard and mutation in `& { ... }`. Prove it: stub the binary, feed the block line-by-line with the guard failing, confirm the mutation marker is absent, then strip the wrapper and confirm it appears. A guard never observed failing is not a guard. |
| Safety proof that fails open | `$DEVSHA` empty made a range query silently become `origin/master..HEAD`, exit 0, and print a plausible integer, which the plan consumed as evidence of safety. A second check exited 128, also read as success. | blocking | Guards must assert on VALUES (`[ ${#DEVSHA} -eq 40 ]`, a hard equality against the planning SHA, a fresh remote-tag vs live-branch SHA comparison), never on exit codes, and must live in the same invocation as the thing they guard. |
| One reason string reused across a group | The dismissal comment for alerts #6-#24 asserted "the test's own assertion over a URL literal defined in the same file". False for at least 16 of 19: some read a file off disk, some assert on a production class attribute, some on captured stdout. Blanket suppression wearing a per-alert costume. A dismissal comment cannot be edited after it is PATCHed. | blocking | One reason string per code SHAPE, each verified by opening the actual cited file. Acceptance criteria must require the strings be distinct AND true, and the audit must group by a discriminator that actually separates them (a base64 prefix of 12 chars collapsed all 26 into 2 groups). |
| Parallel edits to cross-referencing documents | Two agents edited 38-05 and 38-06 simultaneously. 38-06's verification step was written against the pre-fix 38-05 and would have commanded the executor to re-PATCH all four new strings back into the single false one. | blocking | Sequence edits when one document asserts facts about another. Verify cross-file agreement by extracting both sides and comparing bytes, not by reading. |
| Plan step that restores its own stale inputs | 38-01 does `PLANSHA=$(git rev-parse HEAD)` then checks out the phase directory at that SHA. With the remediated plans uncommitted, this silently restored the pre-remediation versions and would have undone five passes. | blocking | 38-01 now hard-fails if `git status --porcelain -- <phase dir>` is non-empty, before `PLANSHA` is taken. Never rely on a checkout of HEAD to carry working-tree work. |
| Verifying config instead of artifact | Packaging correctness read back from `pyproject.toml` passes on a broken tree. It is how a dead wheel survived four milestones. | advisory | Build the artifact and inspect it. Never assert behavior from config text. |
| Plan names one call site when several exist | Wave 3's plan located a path expression at `core/orchestrator.py:814`. It was also at `core/service.py:133` and `:159`. | advisory | Grep the whole package for the pattern before editing, not just the line the plan names. |
| Classifier denies executor dispatch | The harness auto-mode classifier denied `gsd-executor` dispatch for the PR #11 merge twice, including after the operator granted permission. | advisory | Run PR-merging steps inline in the main thread. The orchestrator must then update STATE.md itself, since inline runs produce no per-plan state writes. |
