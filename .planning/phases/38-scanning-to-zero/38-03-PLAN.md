<shell_conventions>
Everything in this plan runs in Git Bash. Four properties of this box were measured directly on
2026-09-09 and every command below is written around them. Do not "simplify" past any of them.

1. **Every fenced block is ONE invocation.** Shell variables do not survive between harness calls,
   so a guard submitted separately from the mutation it guards is not a guard. `set -e` plus an
   explicit value assertion plus `exit 1` is the mechanism. Do not split a fence, and do not feed a
   fence to the shell line by line.

2. **Assert on VALUES, never on exit codes.** Every gate below compares a string read back in the
   same invocation. An exit-code test would pass on a command that succeeded at doing the wrong
   thing.

3. **`rtk git status --porcelain` prints the 4-byte string `ok` on a clean tree.** Measured:
   `rtk git status --porcelain -- .github/workflows` emits `ok`; `rtk proxy git status --porcelain
   -- .github/workflows` emits nothing. `ok` is non-empty, so any emptiness test against the
   filtered form can never pass. **Use `rtk proxy git status --porcelain` wherever emptiness or an
   exact porcelain line is the assertion.** The same class of defect applies to `rtk git log`
   (drops merge commits, caps at 50, returns EMPTY for an all-merge range) and `rtk git diff`
   (reformats, so `^[+-]` matches nothing): use `rtk proxy` for both. `git diff --numstat` passes
   through `rtk proxy` unreformatted.

4. **The mandatory rtk hook rewrites a LEADING `grep` and mangles counts.** Measured against
   `.github/workflows/gitleaks.yml`, which really does carry one top-level `permissions:` key:

   | Form | Result |
   |------|--------|
   | `grep -v "^ *#" FILE \| grep -c "^permissions:"` at top level | prints an rtk header line then `0` |
   | `N=$(grep -v "^ *#" FILE \| grep -c "^permissions:")` | `N=1`, correct |
   | `grep -c PATTERN FILE` at top level | prints an rtk match listing, not a count |
   | `N=$(grep -c PATTERN FILE)` | `N=1`, correct |
   | `grep -cE PATTERN FILE` at top level | `1`, correct (the hook does not rewrite `-cE`) |

   A criterion written as "`grep -v ... | grep -c ...` returns 1" is therefore UNPASSABLE at top
   level, exactly like the `ok` defect above. **Every count in this plan is captured into a shell
   variable with `$( )` and then value-tested.** Command substitution is not rewritten by the hook.
   This also converts each check from "read the output and agree" into a machine assertion, which
   is the stronger form anyway.

Python is `.venv/Scripts/python.exe` with forward slashes, which resolves correctly from Git Bash
on this box. Tests are never `rtk pytest`. `gitleaks` is not installed here and must never be run
locally.
</shell_conventions>
