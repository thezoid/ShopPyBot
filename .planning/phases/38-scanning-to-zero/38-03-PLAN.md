For each distinct `owner/repo@tag`, resolve the tag to a commit SHA and then prove that commit
exists in that repository. Both steps are required: a tag reference that resolves to nothing, or to
an object in a different repository, is exactly the supply chain failure pinning is supposed to
prevent.

```
REPO=actions/checkout
TAG=v7
SHA=$(gh api "repos/$REPO/git/ref/tags/$TAG" --jq 'if .object.type=="tag" then .object.url else .object.sha end')
case "$SHA" in https*) SHA=$(gh api "$SHA" --jq '.object.sha');; esac
echo "$REPO@$TAG -> $SHA"
gh api "repos/$REPO/commits/$SHA" --jq '.sha' 
```

The `case` line is not optional: annotated tags return an object of type `tag`, and taking
`.object.sha` from those yields the tag object's SHA rather than the commit's. Pinning to a tag
object SHA fails at run time.

The final `gh api repos/$REPO/commits/$SHA` must exit 0 and echo the same 40-character SHA. If it
404s, or returns a different SHA, stop. Do not guess and do not fall back to the value in this
