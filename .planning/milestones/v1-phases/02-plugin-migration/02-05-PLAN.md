<objective>
Wave 3: convert `main.py` from the synchronous Selenium loop to an async event loop driven by the plugin registry (D-02, D-03, RESEARCH Pattern 9).

Remove the Selenium driver setup (`get_chromedriver_path`, Chrome `Options`/`Service`, `webdriver.Chrome(...)`) and the CDP `navigator.webdriver` stealth patch (D-02 — nodriver handles stealth, the Phase-1 patch is gone). Replace the `if "amazon.com" in link / elif "bestbuy.com" in link` routing with `registry.route(link)`. Keep the sync pre-flight exactly as-is: AppConfig validation with ValidationError catch, DB initialize + add_items, and the getpass CVV gate (which MUST run before `asyncio.run()` — `input()`/`getpass` must not run inside the async loop, D-03 / RESEARCH Pattern 9). Drive the item loop sequentially: `await plugin.check_availability(link)` then optionally `await plugin.auto_buy(link)`, one item at a time (NO asyncio.gather — deferred, D-03). On exit, `await registry.teardown_all()`.

Thread the CVV to BestBuy: per Plan 04's SUMMARY contract, the BestBuy plugin exposes a `_cvv` attribute; main.py sets it (lazily, just before auto_buy) so the plugin can fill the CVV field. This keeps main.py the only file this plan modifies.

This plan has a human-verify checkpoint at the end: a live async cold-start is the only way to confirm the end-to-end boot (registry discovers plugins, lazy-launches a browser, checks an item). It is gated because it requires a real Chrome process and cannot run in the unit suite.

Purpose: wire the registry + plugins into the running bot, completing the Selenium→nodriver migration in the entry point.
Output: revised `main.py`.
</objective>
