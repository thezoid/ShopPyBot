<objective>
Implement the fan-out dispatcher: the single component that drives all registered notifiers
and guarantees per-channel isolation (NOTIF-01 / success criterion 1).

Purpose: A misconfigured channel (e.g. a bad Discord webhook) must NOT crash the bot or block
the other channels. The dispatcher wraps each `notifier.send(event)` in its own try/except,
logs the failing channel by class name, and continues. The error log must be scrubbed — the
class name + a static message only, never str(exc) (which can embed the webhook URL or Twilio
SID).

Output: `notifications/dispatcher.py` with `NotificationDispatcher`, the package export wired
up in `notifications/__init__.py`, and the fan-out/isolation/secret-scrub tests flipped to
passing.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| notifier exception -> dispatcher log | exception strings may embed secrets (webhook URL, SID) and must not reach the log |
| dispatcher -> notifiers | one untrusted/misconfigured channel must not affect the others |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-11 | Information Disclosure | dispatcher except-block logging | mitigate | Log `notifier.__class__.__name__` + `exc.__class__.__name__` only; never str(exc)/repr(exc); a caplog test asserts a leaked-URL substring is absent (Pitfall 1) |
| T-05-12 | Denial of Service | one channel failure cascading | mitigate | Each send wrapped in its own try/except Exception; failure logged + loop continues; notify() never propagates (NOTIF-01 / SC1) |
| T-05-13 | Denial of Service | bare except swallowing KeyboardInterrupt | mitigate | Use `except Exception` (not bare/BaseException) so Ctrl-C and SystemExit still propagate (Anti-Patterns) |
</threat_model>
