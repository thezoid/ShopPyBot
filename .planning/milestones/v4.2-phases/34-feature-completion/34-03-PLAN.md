<objective>
Compute operator-facing outcome analytics — success-rate and time-to-checkout — from EXISTING confirmed-order (BUY-04) records (FC-02). No new order-capture logic and no new columns: plugin identity is derived from the item `link` hostname via the registry's `domain_patterns`; the two durable buy-flow timestamps (`place_order_attempted_at`, `confirmed_at`) drive time-to-checkout. A PURE `compute_analytics(rows, platform_of)` function makes the fixture assertion exact and DB-free; a read-only `GET /api/analytics` returns aggregate-only JSON (no `link`, no credentials); the dashboard renders headline stat cards + a per-plugin table reusing the v4.1 design system verbatim.

Purpose: Gives the operator a real success-rate + speed signal over data already captured in Phase 19/30, with the metric math isolated in a pure function so correctness is provable against a fixture.
Output: `core/analytics.py`, `models.get_order_analytics_rows_sync`, `BotService.get_analytics`, `GET /api/analytics`, dashboard analytics view, fixture + endpoint tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → GET /api/analytics | unauthenticated local dashboard read of computed order aggregates |
| items table → analytics response | order records (including `link`, which can carry tokens) cross into a JSON response |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-05 | Information Disclosure | /api/analytics response | mitigate | Output is aggregate-only — platform_key + integer/float counts; `link`/URL/order_id/credential fields are never emitted; a test asserts CRED_PATTERN does not match and "link" is not a response key (mirrors the get_status boundary + Phase-26 read-only pattern) |
| T-34-06 | Information Disclosure | link → platform resolution | mitigate | `link` is read ONLY inside get_analytics to derive platform_key via domain_patterns; it never enters the returned dict (resolution happens server-side before aggregation) |
| T-34-07 | Denial of Service | analytics DB read per request | accept | Single indexed read of the items table via asyncio.to_thread (off the event loop, SSE-03); local single-operator dashboard, low request volume |
| T-34-SC | Tampering | new dependencies | accept | No package installs — analytics uses stdlib datetime + existing sqlite3/fastapi; Package Legitimacy Gate is N/A |
</threat_model>
