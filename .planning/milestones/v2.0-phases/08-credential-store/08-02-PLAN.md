<objective>
Implement the two real-storage backends: `KeyringBackend` (OS secret service via `keyring`, with a `_has_real_keyring()` guard against keyring's fail/null backends) and `EncryptedFileBackend` (Fernet AES-128-CBC+HMAC, key derived from a passphrase via scrypt, atomic binary file write). Pin the one net-new dependency, `keyring`.

Purpose: CRED-02 (keyring) and CRED-03 (encrypted file) are the two real at-rest storage forms. The encrypted-file backend is the no-plaintext-on-disk guarantee (CRED-06) and the headless fallback. These are the only backend classes with no codebase analog, so they follow 08-RESEARCH Patterns 2 and 3 verbatim.
Output: KeyringBackend + EncryptedFileBackend + helpers in core/credentials.py; keyring pinned in requirements.txt; the corresponding xfail stubs in tests/test_credentials.py un-xfailed and passing.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| passphrase (env/getpass) → scrypt KDF | User-supplied passphrase derives the Fernet key; never written to disk |
| EncryptedFileBackend → creds.bin | The only at-rest secret form; must be ciphertext, never plaintext |
| KeyringBackend → OS secret service | Secrets handed to Windows Credential Manager / Linux Secret Service |
| pip → keyring install | Third-party package introduced into the dependency tree |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-04 | Information Disclosure | creds.bin at-rest plaintext leak | mitigate | Fernet AES-128-CBC+HMAC over JSON; test_encrypted_file_is_not_plaintext asserts no plaintext secret in raw bytes (Task 3) |
| T-08-05 | Tampering | weak passphrase brute-force on creds.bin | mitigate | scrypt n=2**14 memory-hard KDF (RFC 7914) raises brute-force cost; documented that passphrase strength matters |
| T-08-06 | Spoofing | keyring null/fail backend silently accepts writes that vanish | mitigate | _has_real_keyring() rejects fail.Keyring and null.Keyring before selecting the keyring backend (Task 2) |
| T-08-07 | Tampering | atomic-write race corrupts creds.bin on crash mid-write | mitigate | tempfile.mkstemp + fd closed before os.replace; os.unlink(tmp) on failure (Task 3, Pitfall 6) |
| T-08-08 | Information Disclosure | InvalidToken stack trace leaks passphrase/secret context | mitigate | InvalidToken caught and re-raised as a generic ValueError naming only the env-var SHOPBOT_STORE_PASSPHRASE, never a secret value (Task 3) |
| T-08-SC | Tampering | keyring supply-chain (pip install) | mitigate | Blocking human legitimacy checkpoint (Task 1) verifies keyring on pypi.org before install; pinned to exact ==25.7.0 |
</threat_model>
