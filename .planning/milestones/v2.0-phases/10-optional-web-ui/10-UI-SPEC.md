# Phase 10 — UI Design Contract

> Visual and interaction contract for Phase 10: Optional Web UI (ShopPyBot local FastAPI dashboard).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Source: all design decisions locked in `10-CONTEXT.md` unless otherwise noted.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-written HTML/CSS only |
| Icon library | none — text labels only (e.g. "Start", "Stop", "Remove") |
| Font | system font stack: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif |

No CDN. No frontend build step. A single vendored CSS file at `web/static/dashboard.css`
provides all styling. The file ships with the package. (Source: CONTEXT.md)

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-adjacent gaps, inline badge padding, table cell inner gaps |
| sm | 8px | Button padding block, compact form field gaps, table row padding |
| md | 16px | Default element spacing, input horizontal padding, card padding |
| lg | 24px | Section inner padding, form group gaps |
| xl | 32px | Section vertical gap, dashboard main padding |
| 2xl | 48px | Page-level vertical rhythm between the four named sections |
| 3xl | 64px | Not used — pages have no hero/marketing-level whitespace |

Exceptions (all 4-pt aligned, just outside the named token set):
- form inputs / submit buttons min-height 36px (36 = 4×9; sized for a comfortable tap/click target).
- non-local warning banner padding 12px 16px (12 = 4×3; tighter than the `md` card padding so the banner reads as an alert strip, not a section card).

## Typography

System font stack throughout. No external font load.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / table cell | 14px | 400 (normal) | 1.5 |
| Label / input label | 14px | 600 (semibold) | 1.4 |
| Section heading (h2) | 18px | 600 (semibold) | 1.2 |
| Page title (h1) | 22px | 600 (semibold) | 1.2 |
| Log panel / inline form error (monospace + small) | 12px | 400 (normal) | 1.4 |

Two weights (400, 600). Four primary sizes (14, 18, 22 px — the two 14px roles differ
in weight only) plus one small 12px size reserved for the dense monospace log panel and
inline form-error text. This is intentional for a utilitarian admin tool; no decorative
or display typeface is needed.

## Color

Utilitarian neutral palette. Works in default browser light mode. No dark-mode toggle
required (local admin tool; deferred). (Source: CONTEXT.md aesthetic direction)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #f5f5f5 | Page background, main content area |
| Secondary (30%) | #ffffff | Section cards / panel backgrounds, table rows |
| Accent (10%) | #2563eb | Primary action buttons (Start bot, Add item, Save config, Set credential) |
| Destructive | #dc2626 | Stop bot button; Remove item button; non-local host warning banner |
| Border / divider | #d1d5db | Table borders, card outlines, form input borders |
| Text primary | #111827 | All body text, headings, labels |
| Text secondary | #6b7280 | Placeholder text, "unset" credential status, empty-state body copy |
| Status: running | #16a34a | Bot status indicator dot when bot is running |
| Status: stopped | #6b7280 | Bot status indicator dot when bot is stopped/idle |
| Feedback: success | #16a34a | Inline success message after credential save or config save |
| Feedback: error | #dc2626 | Inline error message after failed API call |

Accent reserved for: Start button, Add Item submit, Set Credential submit, Save Config submit.
No other elements use #2563eb.

Destructive (#dc2626) reserved for: Stop button, Remove row action, non-local warning banner background
(banner uses a lighter tint: #fee2e2 background with #dc2626 text/border).

## Layout

Four named sections render on a single scrollable page in this order:

1. Controls / Status
2. Items
3. Credentials
4. Config

Primary focal point: the bot status indicator + Start/Stop controls in Section 1 —
the first card on the page and the highest-frequency action; it carries the page's
single accent (Start) and destructive (Stop) buttons so the eye lands there first.

Each section is visually grouped as a card (white background, 1px #d1d5db border,
4px border-radius, 24px inner padding). Section headings use the h2 type role.
No sidebar. No tabbed navigation. No multi-page routing. All content loads on
initial page render; the status/logs panel updates in place via JS polling.

Page max-width: 900px, centered with auto margins.
On viewports narrower than 640px: full-width with 16px side padding.

## Section Contracts

### 1. Controls / Status

Elements:
- Bot status indicator: a 10px circle + text label ("Running" / "Stopped / Idle")
- "Start Bot" button (accent): calls POST /api/bot/start
- "Stop Bot" button (destructive): calls POST /api/bot/stop
- Recent logs panel: scrollable pre/code block, fixed height 200px, updated by
  polling GET /api/logs every 2 seconds; shows last 50 lines; monospace 12px font

States:
- Bot running: status dot is #16a34a, "Running" label; Start button is disabled
  (opacity 0.4, cursor not-allowed); Stop button is enabled
- Bot stopped: status dot is #6b7280, "Stopped" label; Stop button is disabled;
  Start button is enabled
- Log panel during load error: retains last known lines, no spinner

### 2. Items

Elements:
- Table: columns = Name, URL, Auto Buy, Quantity, Remove
- Each row: "Remove Item" is a destructive text button/link (color #dc2626)
- Add form below the table: four fields (Name [text], URL [text], Auto Buy [checkbox],
  Quantity [number, min 1]) + "Add Item" submit (accent button)
- Empty state (no items): shown inside the table body area

States:
- Table has items: rendered as standard rows
- Table empty: show "No items tracked yet." (secondary text color) + "Add one below."
- Add form validation error (blank name or URL): inline error beneath the field,
  text color #dc2626, 12px, no pop-up/modal
- Remove: no modal confirmation — button is clearly labelled "Remove Item" in destructive
  color, single click sends DELETE; row disappears on success; on error show inline
  message in the row area
- After successful add: form resets, new row appears at the bottom of the table

### 3. Credentials

Elements:
- List (not a table): each known credential key shown as "KEY_NAME — Set" or
  "KEY_NAME — Not set"; status only, never the current value
- Inline form per key: a single password input + "Save Credential" button (accent)
  The input field placeholder text is "Enter new value" (never pre-filled)
- No "reveal" or "copy" controls exist anywhere in this section

States:
- Key is set: label text "#6b7280 / Not set" changes to "Set" (black/primary text)
  after a successful POST
- Save success: inline message "Saved." in #16a34a beneath the input; input clears
- Save error: inline message "Failed to save. Try again." in #dc2626 beneath the input
- The HTTP response contains ONLY {"status": "ok"} or {"status": "error", "detail": "..."} —
  the secret value is absent from the response body in all cases

### 4. Config

Elements:
- Two text/number inputs: test_mode (checkbox) and logging_level (number 0–5)
- Platform/notifier enable toggles: one checkbox per platform/notifier (amazon, bestbuy,
  walmart, target, gamestop, squareenix, newegg, discord, email, sms, sound)
- "Save Config" button at the bottom (accent)

States:
- After save success: inline "Saved." in #16a34a
- After save error: inline "Failed to save. Check server logs." in #dc2626
- Unknown config key submitted (dev/test only): 422 response, server does not save

## Non-Local Host Warning Banner

Triggered when `--host` is not `127.0.0.1` / `localhost`.

Rendered as a full-width banner at the top of the page ABOVE all sections.
Background: #fee2e2. Border-bottom: 1px solid #dc2626. Text color: #dc2626.
Font-weight: 600. Padding: 12px 16px.

Copy (exact): "Warning: this dashboard is reachable beyond localhost. Credential
management is exposed on a non-local interface. Use only on a trusted private network."

The same warning is also printed to stderr before uvicorn starts (CLI layer, not HTML).

## Interaction Contracts

### Polling (JS)

- `GET /api/status` and `GET /api/logs` polled every 2000ms via `fetch`.
- On network error: silently retry next tick; do not show error toast for transient
  connection failures (local-only tool — a 2s gap is not alarming).
- On 3 consecutive failures: show inline "Connection lost — retrying..." in the
  log panel area (secondary text color, non-disruptive).
- No WebSocket or SSE. No build step. No bundler. Inline `<script>` in the template.

### Form Submission (JS)

- All forms submit via `fetch` (no full page reload).
- Disable the submit button while the request is in flight (prevent double-submit).
- Re-enable submit and show inline feedback (success/error) on response.
- Credentials: clear the password input after success regardless of outcome.

### CSRF Defense

- Server validates `Origin` and `Host` headers on all state-changing POST/DELETE
  routes (credentials, items, config, bot start/stop).
- Mismatched origin: server returns 403; JS shows "Request rejected (security check)."
  in #dc2626 beneath the triggering form.

## Accessibility Basics

- All form inputs have associated `<label>` elements (not placeholder-only).
- Color is never the SOLE differentiator for status (status dot + text label; "Set"/"Not set" text).
- Buttons use `<button type="submit">` or `<button type="button">` — no `<div>` click handlers.
- Tab order follows visual order (single-column layout; natural DOM order is correct).
- Contrast ratios: #111827 on #f5f5f5 = ~16:1 (passes WCAG AA); #dc2626 on #ffffff = ~5.9:1
  (passes WCAG AA large text); accent #2563eb on #ffffff = ~7.2:1 (passes WCAG AA).
