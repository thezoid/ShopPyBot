<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| terminal stdin → setup | secret values typed by the user via getpass |
| CLI args → config set | key/value pair that becomes a config.yml write |
| CLI → config.yml file | atomic write of backend + allowlist scalars |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-04 | Information Disclosure | setup secret echo / confirmation output | mitigate | getpass.getpass (no echo); confirm by KEY NAME only — print f"Stored: {key}" never the value; test_setup_no_secret_echo asserts capsys stdout excludes the secret (HIGH severity, mitigated) |
| T-09-05 | Information Disclosure | secret leaking into config.yml | mitigate | setup writes ONLY credentials.backend to config.yml via _atomic_yaml_write; secret values go to get_store().set (CredentialStore), never to YAML (CRED-06) |
| T-09-06 | Tampering | config set writing arbitrary keys (allowlist bypass) | mitigate | ALLOWLIST gate: unknown key returns/exits 2 before any file read/write; only test_mode/logging_level are writable (HIGH severity, mitigated) |
| T-09-07 | Tampering | YAML injection / unsafe load on config.yml | mitigate | yaml.safe_load only (never yaml.load); dumped values are coerced Python primitives |
| T-09-08 | Tampering / DoS | partial config.yml write on crash | mitigate | tempfile.mkstemp + os.replace atomic write; unlink temp + re-raise on failure (copy of EncryptedFileBackend._save) |
| T-09-09 | Denial of Service | getpass under non-interactive stdin (CI/pipe) | mitigate | _prompt_secret catches (EOFError, GetPassWarning) and treats as skip — no crash |
</threat_model>
