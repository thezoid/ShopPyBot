<objective>
Convert `main.py` into a thin front-end shim. It keeps the v1 pre-flight (AppConfig validation, DB seed from config items, getpass CVV gate) and then routes the actual run through `BotService(...).run(cvv)` instead of calling `asyncio.run(async_main(...))` directly. `python main.py` keeps working verbatim for users who never adopt the new entry point.

Purpose: MOD-02 (no bot logic in the front-end — the shim is a thin adapter over BotService) + MOD-03 (the `python main.py` shim half).
Output: a slimmed `main.py` delegating to BotService, and an updated `tests/test_main_wiring.py` that asserts delegation-to-service.

⚠ FLAGGED EXCEPTION TO "EXISTING SUITE UNMODIFIED": `tests/test_main_wiring.py` currently asserts that `main` itself calls `asyncio.run(async_main(...))` (it patches `main.asyncio.run` and `main.async_main`). Once the run is routed through `BotService.run()`, those `asyncio.run`/`async_main` calls live inside `core/service.py`, NOT in `main` — so `patch("main.asyncio.run")` can no longer intercept them and two of its tests would fail by construction. Per the planning directive this is the ONE explicitly-allowed test change: the delegation seam moved from `main→orchestrator` to `main→BotService→orchestrator`. The update REPLACES the now-invalid "main calls asyncio.run with an async_main coroutine" assertions with "main delegates to BotService.run() with the collected CVV", and PRESERVES every other assertion (CVV gate in/out of test_mode, ValidationError→SystemExit(1)). Coverage is not weakened: the same security/behavior contracts are still proven, just at the new seam.
</objective>
