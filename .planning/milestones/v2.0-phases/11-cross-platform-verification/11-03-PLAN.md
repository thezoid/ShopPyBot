<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| legacy filesystem -> OS-standard dir | migration reads repo-relative files and writes them to the user data dir |
| migration -> logger | migration emits log lines that must never carry secret values |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-06 | Information Disclosure | migration relocating a plaintext secret to a less-protected location | mitigate | creds.bin is copied byte-for-byte with shutil.copy2 (stays Fernet+scrypt encrypted); destination (%LOCALAPPDATA% / ~/.local/share, user-owned) is strictly MORE protected than repo-relative data/. No plaintext secret exists to relocate; env-var backend has nothing on disk to migrate. test_migration_moves_creds_verbatim asserts byte-identity. (HIGH severity — fully mitigated, no unmitigated HIGH ships.) |
| T-11-07 | Information Disclosure | a secret value leaking into a migration log line | mitigate | writeLog receives only f"Migrated {src} -> {dst}" path strings; the function never reads creds.bin content. test_migration_logs_paths_not_secrets asserts no creds bytes appear in any logged message. |
| T-11-08 | Tampering / Denial of Service | migration corrupting or destroying the DB or creds | mitigate | copy2 BEFORE unlink: if copy fails, src is untouched; the `src.exists() and not dst.exists()` guard makes a second run a no-op and never overwrites an existing destination. test_migration_idempotent + test_migration_skips_when_dst_exists cover this. |
| T-11-09 | Tampering | SHOPBOT_DATA_DIR / repo-root path traversal during migration | accept | Paths come from platformdirs (trusted) or a user/CI-set env var the user already controls; pathlib normalizes; no untrusted network input. Low risk per RESEARCH Security Domain. |
</threat_model>
