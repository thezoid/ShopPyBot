<objective>
Add the three confirmation columns to the `items` table via the established idempotent
`ALTER TABLE` migration pattern, and add `update_item_confirmed_sync` — the writer that
sets `purchased=1`, `order_id`, and `confirmed_at` together. This is the DB foundation
(BUY-04) that the orchestrator's `("confirmed", ...)` write tag (Plan 04) routes to, and
the `order_id` column is the idempotency anchor Phase 21's cart-retry will read.

Purpose: A confirmed order must be persisted with its captured order id and timestamp so
`purchased` is only ever set alongside a real order number, never on a button click.
Output: Migrated `items` schema + `update_item_confirmed_sync` in `models.py`, with
migration-idempotency and writer tests in `tests/test_models.py`.

Scope guard: `checkout_attempts` is added with `NOT NULL DEFAULT 0` now but is NEVER
incremented in this phase. The increment strategy is owned by Phase 21 (retry). Adding
the column only.
</objective>
