<objective>
Wrap the orchestrator's buy attempt in a cart-retry loop driven by `with_retry` + a `RetryPolicy` built from `CheckoutConfig` (`max_cart_retries`, `backoff_base`, `backoff_jitter`). Extract the retryable unit `_attempt_buy(plugin, link) -> tuple[bool, str | None]` (auto_buy + confirmation detection, NO enqueue) so the existing 40-line `_try_auto_buy` drops under the 30-line max. Before each attempt: increment `checkout_attempts` (via `on_attempt`) and re-read `(purchased, order_id)` — a confirmed `order_id` short-circuits with zero further place-order attempts (BUY-05 no-double-buy). The confirmation/legacy `write_queue.put()` enqueue stays OUTSIDE the retry loop, preserving the P19 WR-02 exactly-one-enqueue invariant.

Purpose: Cart-retry recovers a failed/misdetected checkout up to a configured bound without ever re-submitting an order that already confirmed (BUY-05), using the single shared backoff source (REL-08).
Output: refactored `core/orchestrator.py` (new `_attempt_buy` + cart-retry wrapper), `tests/test_cart_retry.py`.
</objective>
