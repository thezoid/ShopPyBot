<objective>
Wrap each checkout DOM stage in both plugins under its OWN `async with asyncio.timeout(step_timeout_secs)` and track progress via `self._checkout_stage`, set BEFORE each stage. Add the `self._checkout_stage = ""` default to `RetailerPlugin.__init__` so the attribute always exists. Amazon gets 6 timed stages, BestBuy gets 8 (per the RESEARCH DOM stage map). On a step timeout, the existing `except Exception` handler (which catches `asyncio.TimeoutError` since it subclasses `Exception` in Python 3.11) logs the stage and returns False — the item is NOT immediately re-submitted (the orchestrator decides retries in Plan 04).

Purpose: A slow form-fill must abort cleanly at its own DOM boundary, never mid-flight on the CVV entry or place-order click — a single outer timeout would risk a half-submitted order (BUY-06). `_checkout_stage` leaves a post-mortem breadcrumb.
Output: one-line addition to `core/plugin_base.py`; per-stage timeout wrapping in both plugin `auto_buy()` bodies; plugin tests asserting stage tracking + clean abort.

Per-ITEM ceiling (item_timeout_secs) is explicitly OUT OF SCOPE — Phase 22 owns it. This plan implements per-STEP timeouts only.
</objective>
