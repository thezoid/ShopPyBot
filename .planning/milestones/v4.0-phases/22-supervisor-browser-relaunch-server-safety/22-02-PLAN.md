<objective>
Harden `run_plugin` in `core/orchestrator.py` with two independent reliability layers: SQLite read isolation on the items-list read (REL-05) and a per-item `asyncio.timeout(item_timeout_secs)` ceiling around each check/buy cycle (REL-06). Add a `cfg` parameter to `run_plugin` so it can read `CheckoutConfig.item_timeout_secs`.

Purpose: A locked DB on the read path must degrade gracefully (skip one poll cycle), not kill the plugin's poll loop. A stalled page or long captcha pause on one item must not freeze the other items on that retailer; the per-item ceiling pairs with Phase 21's per-step timeouts (per-step bounds each DOM action; per-item bounds the whole item cycle). `write_queue.put()` calls stay outside the timeout so a timed-out item never orphans a pending DB write.

Output: Modified `run_plugin` (cfg param + read isolation + per-item timeout); new orchestrator tests covering both behaviors.
</objective>
