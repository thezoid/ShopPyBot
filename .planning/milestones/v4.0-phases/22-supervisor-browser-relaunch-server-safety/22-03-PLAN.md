<objective>
Add the keystone `supervise()` wrapper coroutine plus the `_is_browser_dead_exc` helper to `core/orchestrator.py`, and wire `async_main`'s TaskGroup to run each plugin through `supervise()` instead of bare `run_plugin`. This absorbs every plugin crash before the TaskGroup boundary (REL-01), restarts with exponential backoff, parks a plugin after its failure budget is exceeded with an operator notification (REL-02), and triggers `relaunch()` (Plan 01) with proxy re-assignment on browser death.

Purpose: REL-01 is the reliability keystone -- `asyncio.TaskGroup` cancels every sibling when any child task raises an unhandled exception. A wrapper that catches `Exception` (but re-raises `CancelledError`, which inherits `BaseException`) guarantees one plugin crash can never kill the others. The failure budget (N = `CheckoutConfig.alert_on_errors`, default 3, within a ~600s rolling deque window) parks a crash-looping plugin and notifies the operator. Restart backoff reuses `compute_delay` from `core/retry.py` (REL-08 single source). On browser death, the supervisor advances the proxy then calls `plugin.relaunch()` before re-entering the poll loop.

Output: `supervise()` + `_is_browser_dead_exc` module-level definitions; modified `async_main` create_task block (now passing `cfg` to both `supervise` and through to `run_plugin`); new `tests/test_supervisor.py`.
</objective>

| Boundary | Description |
|----------|-------------|
| browser process -> plugin coroutine | a dead/disconnected Chrome surfaces as ConnectionError/RuntimeError/ConnectionClosed crossing into supervise() |
| plugin crash -> TaskGroup | an unhandled Exception would otherwise cancel all sibling plugin coroutines |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01 | Denial of Service | TaskGroup sibling cancellation | mitigate | supervise() catches Exception (not BaseException) so one crash cannot cancel siblings; CancelledError re-raised for clean shutdown |
| T-22-02 | Denial of Service | crash-loop on a permanently-broken plugin | mitigate | failure budget (alert_on_errors within 600s) parks the plugin; no unbounded restart loop |
| T-22-03 | Information Disclosure | park notification + crash/relaunch logs | mitigate | NotificationEvent for park uses empty item_name/item_url; all log calls use exc.__class__.__name__, never str(exc) |
| T-22-SC | Tampering | npm/pip/cargo installs | accept | no package installs in this phase (stdlib + existing deps only; RESEARCH Package Legitimacy Audit: none) |
</threat_model>
