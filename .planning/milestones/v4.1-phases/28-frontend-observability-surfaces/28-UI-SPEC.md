## Color Tokens

All color tokens are inherited from `tokens.css`. Phase 28 uses existing tokens via
CSS classes only. Zero new token declarations are added.

### Staleness Band Mapping (OBS-02)

Server computes `heartbeat_age_secs`; client applies one of three CSS classes.

| Band | Condition | CSS Class | Token Used | Light Value | Dark Value |
|------|-----------|-----------|------------|-------------|------------|
| Fresh | `heartbeat_age_secs < 30` | `.heartbeat-ok` | `--color-status-ok` | `#16a34a` | `#22c55e` |
| Stale | `30 <= heartbeat_age_secs < 60` | `.heartbeat-warn` | `--color-status-warn` | `#d97706` | `#f59e0b` |
| Dead | `heartbeat_age_secs >= 60` or `null` | `.heartbeat-err` | `--color-status-err` | `#dc2626` | `#ef4444` |

`null` / sentinel value (plugin never heartbeated): treated as dead band (`.heartbeat-err`).
Display text: "never" instead of a numeric age.

### Status Badge Mapping (OBS-01)

Maps the `status` field from `get_status()` plugin snapshot to an existing status-dot
variant or badge class.

| Status Value | CSS Class on badge | Token | Visual |
|--------------|-------------------|-------|--------|
| `"running"` | `.badge-ok` | `--color-status-ok` | Green dot + "Running" text |
| `"stopped"` | `.badge-neutral` | `--color-status-neutral` | Grey dot + "Stopped" text |
| `"error"` | `.badge-err` | `--color-status-err` | Red dot + "Error" text |
| any other | `.badge-neutral` | `--color-status-neutral` | Grey dot + status value as text |

### Log-Level Color Mapping (OBS-06)

Applied as CSS class on each log line `<span>` element.

| Level | CSS Class | Token | Rendering |
|-------|-----------|-------|-----------|
| `ERROR` | `.log-level-error` | `--color-status-err` | Red text |
| `WARNING` | `.log-level-warn` | `--color-status-warn` | Amber text |
| `INFO` | `.log-level-info` | `--color-text` | Default text color (no override needed) |
| `DEBUG` | `.log-level-debug` | `--color-text-muted` | Muted text |
| `TRACE` | `.log-level-trace` | `--color-text-muted` | Muted text (same as DEBUG) |
| unknown | `.log-level-info` | `--color-text` | Default text color |

Level is parsed from the `[LEVEL]` prefix in each log line string (regex:
`/^\[(\w+)\]/`). If no match, default to `.log-level-info`.

### Color 60/30/10 Budget (Phase 28 extension)

| Budget | Token | Phase 28 Usage |
|--------|-------|----------------|
| 60% dominant | `--color-bg` | Page background (unchanged) |
| 30% secondary | `--color-surface` | Health cards, chart containers, log panel, confirmed-buys table card |
| 10% accent | `--color-accent` | "Follow" toggle active state only (see below) |
| Semantic: status | `--color-status-ok/warn/err/neutral` | Staleness bands, badges, log-level colors |

Accent (`--color-accent`) reserved for Phase 28:
- "Follow" toggle button active state (`.btn-accent` when follow is ON)
- Input `:focus-visible` ring on filter controls (inherited from Phase 25)

Destructive (`--color-destructive`) usage in Phase 28:
- `.badge-err` and `.log-level-error` (both map to `--color-status-err` which equals `--color-destructive` in light mode; use `--color-status-err` for semantic clarity)
- No new destructive actions in Phase 28

```javascript
function heartbeatClass(ageSecs) {
  if (ageSecs === null || ageSecs === undefined) return 'heartbeat-err';
  if (ageSecs < 30)  return 'heartbeat-ok';
  if (ageSecs < 60)  return 'heartbeat-warn';
  return 'heartbeat-err';
}
```

```javascript
function badgeClass(status) {
  if (status === 'running') return 'badge-ok';
  if (status === 'error')   return 'badge-err';
  return 'badge-neutral';
}
function dotClass(status) {
  if (status === 'running') return 'running';
  if (status === 'error')   return 'error';
  return 'stopped';
}
```

### 28-C2: Uptime in Header (OBS-09)

**Element:** `<span id="header-uptime" class="text-secondary">` — already in DOM from Phase 25.

**JS render:** `renderUptime(uptimeSecs)` called from `pollStatus()`.

**Humanization logic:**

```javascript
function humanizeUptime(secs) {
  if (!secs || secs < 0) return '';
  const h = Math.floor(secs / 3600);
  const m = Math.floor((secs % 3600) / 60);
  if (h > 0) return `Up ${h}h ${m}m`;
  return `Up ${m}m`;
}
```

Result set via `document.getElementById('header-uptime').textContent = humanizeUptime(data.uptime_secs)`.
When bot is stopped (`uptime_secs` is 0 or absent), set `textContent` to `''` (empty).

### 28-C3: Price Chart (per item, OBS-05)

**Placement:** Inside each item row in `#section-items`, as a `<div>` injected below
the `<tr>` (the table row is followed by a `<tr>` containing a full-colspan `<td>`
that holds the chart container, or the chart `<div>` is inserted directly below the
table into a per-item expandable area — executor may choose the simpler DOM approach
that avoids nested divs inside `<tr>` constraints).

Recommended approach: a `<div id="chart-{link_b64}" class="chart-container">` inserted
as a sibling below `#items-table`, grouped with the item by `data-link` attribute.
Each item row in the table carries `data-link="{link_b64}"` so charts align to items.

**JS render function signature:**

```javascript
async function loadPriceChart(itemLink) { ... }
```

Called for each item during `loadItems()`. Steps:
1. Compute `link_b64 = btoa(itemLink)` (standard base64, not URL-safe — Phase 26
   endpoint uses `urlsafe_b64decode` with padding; use URL-safe: replace `+` with `-`
   and `/` with `_`, keep `=` padding — same pattern as `removeItem()` in existing code).
2. `GET /api/price-history/{link_b64}`
3. If `series.length === 0`: render `.chart-empty` div with empty-state copy.
4. If `series.length === 1`: render uPlot with `showMarkers: true` (point markers).
5. If `series.length >= 2`: render standard uPlot line chart.

**uPlot config:**

```javascript
const opts = {
  width:  containerEl.clientWidth || 300,
  height: 120,
  series: [
    {},
    { stroke: getComputedStyle(document.documentElement)
               .getPropertyValue('--color-accent').trim(),
      width: 2,
      points: { show: seriesData[1].length < 2 } }
  ],
  axes: [
    { stroke: getComputedStyle(document.documentElement)
               .getPropertyValue('--color-text-muted').trim() },
    { stroke: getComputedStyle(document.documentElement)
               .getPropertyValue('--color-text-muted').trim() }
  ],
  scales: { x: { time: true } },
};
const data = [
  seriesData[0],   // Unix timestamps (seconds)
  seriesData[1],   // prices (numbers)
];
new uPlot(opts, data, containerEl);
```

Colors are read from CSS custom properties at render time so they adapt to theme.
No hardcoded hex passed to uPlot.

**Line rendering:**

```javascript
function appendLogLine(lineText) {
  const span = document.createElement('span');
  span.className = 'log-line ' + logLevelClass(lineText);
  span.textContent = lineText;
  bufferEl.appendChild(span);
}
function logLevelClass(line) {
  const m = line.match(/^\[(\w+)\]/);
  if (!m) return 'log-level-info';
  const lvl = m[1].toUpperCase();
  const map = { ERROR: 'log-level-error', WARNING: 'log-level-warn',
                INFO: 'log-level-info', DEBUG: 'log-level-debug',
                TRACE: 'log-level-trace' };
  return map[lvl] || 'log-level-info';
}
```

**DOM cap (OBS-07):** After appending, trim oldest children if buffer exceeds 500 lines:

```javascript
const MAX_LOG_LINES = 500;
while (bufferEl.children.length > MAX_LOG_LINES) {
  bufferEl.removeChild(bufferEl.firstChild);
}
```

**Follow / pause-on-scroll logic:**

```javascript
let logFollowEnabled = true;

// Pause when user scrolls up
bufferEl.addEventListener('scroll', () => {
  const atBottom = bufferEl.scrollHeight - bufferEl.scrollTop
                   <= bufferEl.clientHeight + 8;  // 8px threshold
  if (!atBottom && logFollowEnabled) {
    logFollowEnabled = false;
    followBtn.classList.remove('btn-accent');
    followBtn.setAttribute('aria-pressed', 'false');
  }
});

// Resume on manual toggle
followBtn.addEventListener('click', () => {
  logFollowEnabled = !logFollowEnabled;
  followBtn.classList.toggle('btn-accent', logFollowEnabled);
  followBtn.setAttribute('aria-pressed', String(logFollowEnabled));
  if (logFollowEnabled) {
    bufferEl.scrollTop = bufferEl.scrollHeight;
  }
});

// After each render, auto-scroll if following
function maybeScrollToBottom() {
  if (logFollowEnabled) bufferEl.scrollTop = bufferEl.scrollHeight;
}
```

**Filter wiring:** Level dropdown and search input each trigger a fresh
`pollLogs()` on `change` / `input` events (debounced ~300ms for search input).
The `n=500` parameter is fixed.

## Interaction States — All Four Surfaces

### Loading State

Each surface renders a loading placeholder on initial page load. Shown until the
first successful fetch resolves.

| Surface | Loading copy | Element |
|---------|-------------|---------|
| Health cards | "Loading plugin status..." | `<p class="text-secondary">` inside `.health-grid` |
| Confirmed-buys table | one empty `<tbody>` (no spinner; table structure renders immediately) | `#buys-tbody` empty |
| Price charts | "Loading..." inside `.chart-container` | `.chart-empty` with loading text |
| Log viewer | `#log-buffer` empty (no explicit loading message) | — |

### Empty State

| Surface | Empty condition | Copy | Element |
|---------|----------------|------|---------|
| Health cards | `statusPayload.plugins` is empty or absent | "No plugins registered." | `<p class="text-secondary">` inside `.health-grid` |
| Confirmed-buys table | `confirmed_orders` array is empty | "No confirmed orders yet." | single `<tr>` with `<td colspan="4" class="text-secondary">` |
| Price chart (per item) | `series` array is empty (non-Amazon plugin) | "No price history available for this plugin." | `<div class="chart-empty">` |
| Log viewer | no lines returned | "No log lines match the current filter." | `<p class="text-secondary">` inside `#log-buffer` |

### Error State

Shown when the `fetch()` for that surface rejects or returns a non-2xx status.
Each surface fails independently — an error in one does not affect others.

| Surface | Error copy | Element |
|---------|-----------|---------|
| Health cards | "Failed to load plugin status. Check server logs." | `<p class="text-secondary">` inside `.health-grid` |
| Confirmed-buys table | "Failed to load order history. Check server logs." | single `<tr>` with `<td colspan="4" class="text-secondary">` |
| Price chart (per item) | "Failed to load price history." | `<div class="chart-empty">` |
| Log viewer | "Failed to load logs. Retrying..." | `<p class="text-secondary">` inside `#log-buffer` |

Error states do NOT replace the section container or heading — only the inner content
area changes. The section card and `<h2>` remain visible.

### Populated State

All sections render normally per the component specs above.
